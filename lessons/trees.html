In simple words

A node is a value with a left and a right child — that's the whole structure. Almost every tree operation costs O(h), the height.

Balanced, a million nodes is only about 20 levels deep. Skewed, it's a linked list in disguise and h equals n.

In a binary search tree everything in the left subtree is smaller and everything in the right subtree is bigger — for the whole subtree, not just the child.

Think of it like…
A family tree. To find someone you start at the top and go down one branch; you never have to look at the other side of the family.

Key ideas

  • The recursion template: handle null first, solve left, solve right, combine. Most easy tree problems are exactly this shape, and most tree bugs are a missing null check.
  • Inorder on a BST gives sorted order. That's the 5-second way to check whether a tree really is a BST.
  • Validate a BST with bounds, not just the children. Going left tightens the high bound, going right tightens the low bound.
  • Lowest common ancestor: search both nodes; if one is found on the left and one on the right, this node is the answer. On a BST just walk down while both values are on the same side.
  • The answer comes from below: for diameter and 'is it balanced', each child returns a number and the parent uses it — one pass instead of recomputing the height at every node.
  • Too deep to recurse? Use your own stack. Measured in Java 21: a skewed tree of 10,000 nodes recurses fine, 100,000 throws StackOverflowError.

Java code

// Maximum depth — LeetCode 104 (the template)
int depth(TreeNode n) {
    if (n == null) return 0;                       // write this FIRST
    return 1 + Math.max(depth(n.left), depth(n.right));
}

// Validate a BST — LeetCode 98 (carry the bounds)
boolean valid(TreeNode n, Integer lo, Integer hi) {
    if (n == null) return true;
    if (lo != null && n.val <= lo) return false;
    if (hi != null && n.val >= hi) return false;
    return valid(n.left, lo, n.val) && valid(n.right, n.val, hi);
}
// Root 5, right child 6, and 6's left child 4 looks fine next to
// every parent — but it is NOT a BST. Inorder gives 1, 5, 4, 6, 7.

// Lowest common ancestor — LeetCode 236
TreeNode lca(TreeNode n, TreeNode p, TreeNode q) {
    if (n == null || n == p || n == q) return n;
    TreeNode l = lca(n.left,  p, q);
    TreeNode r = lca(n.right, p, q);
    if (l != null && r != null) return n;          // they split here
    return (l != null) ? l : r;
}

// Inorder without recursion — the lesson 10 stack
List<Integer> inorder(TreeNode root) {
    List<Integer> out = new ArrayList<>();
    Deque<TreeNode> st = new ArrayDeque<>();
    TreeNode cur = root;
    while (cur != null || !st.isEmpty()) {
        while (cur != null) { st.push(cur); cur = cur.left; }
        cur = st.pop();
        out.add(cur.val);
        cur = cur.right;
    }
    return out;
}

Interview traps to remember

  • Validating a BST: comparing a node only with its immediate children is not enough. Root 5 with right child 6 and 6's left child 4 passes that check and is still not a BST, because 4 sits in 5's right subtree. Carry a low and a high bound down instead.
  • The 5-second check: run an inorder traversal. A real BST comes out sorted; the tree above gives 1, 5, 4, 6, 7.
  • Write the null case first. Most tree bugs are a missing if (node == null).
  • Recursion depth: measured in Java 21, a skewed tree of 10,000 nodes recurses fine but 100,000 throws StackOverflowError. Use your own stack for very deep trees.
  • TreeMap vs HashMap: TreeMap and TreeSet are balanced trees — sorted keys and O(log n), with floorKey and ceilingKey. HashMap is O(1) average with no order at all.
  • HashSet only LOOKS sorted: new HashSet<>(List.of(5, 1, 3)) prints [1, 3, 5] because small integers hash to themselves. With strings the illusion breaks: pear, apple, fig prints [apple, pear, fig].

Spot it when

  • Anything described as a hierarchy, a parent and children, or a folder structure.
  • 'Sorted output', 'kth smallest' or 'validate' on a BST — that's inorder.
  • 'Level by level' or 'right side view' — that's BFS with a queue.
  • 'Diameter', 'balanced' or 'max path sum' — return information upward.

★ Draw the tree, write the null case first, and say out loud what each recursive call returns. Also know that TreeMap and TreeSet are balanced trees — sorted keys, O(log n) — while a HashSet has no order at all. It only looks sorted with small integers, because they hash to themselves.
