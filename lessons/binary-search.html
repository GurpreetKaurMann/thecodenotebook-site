In simple words

Binary search needs one thing: order. Look at the middle and you can throw away a whole half. That's O(log n) — one billion sorted values takes only 30 steps, because 230 is just over a billion.

The bigger idea: it also works when there is no array at all. If your answer is a number in a range and your check never flips back from yes to no, you can binary search the answer.

Think of it like…
Guessing a number between 1 and 100. Each guess in the middle halves what's left, so seven guesses is always enough.

Key ideas

  • Always write lo + (hi - lo) / 2. With lo = 2_000_000_000 and hi = 2_100_000_000, (lo + hi) / 2 overflows to -97483648.
  • Two rules that stop infinite loops: lo <= hi pairs with hi = mid - 1, and every branch must move past mid.
  • Duplicates: when you find the target, save the index and keep shrinking that side. Going left gives the first occurrence, going right gives the last.
  • Rotated array: at every step at least one half is still perfectly sorted. Check which half, ask whether the target sits inside it, and go there.
  • Search the answer: minimum speed, minimum capacity, minimum days. The check is monotonic — if a value works, every bigger one works — so you binary search the range.
  • Arrays.binarySearch returns −(insertion point) − 1 when the value is missing. Searching 4 in {1, 3, 5, 7} returns -3, so it hands you the insert position for free.
  • TreeMap gives you floorKey and ceilingKey — binary search over a map, all in O(log n).

Java code

// The template — memorise this shape
int search(int[] nums, int target) {
    int lo = 0, hi = nums.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;      // never (lo + hi) / 2
        if (nums[mid] == target) return mid;
        if (nums[mid] < target) lo = mid + 1;
        else                    hi = mid - 1;
    }
    return -1;
}

// First occurrence with duplicates — LeetCode 34
int first(int[] nums, int target) {
    int lo = 0, hi = nums.length - 1, ans = -1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (nums[mid] == target) { ans = mid; hi = mid - 1; }   // keep going left
        else if (nums[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return ans;      // {5,7,7,8,8,10}, target 8 -> 3
}

// Binary search on the ANSWER — Koko Eating Bananas, LeetCode 875
int minSpeed(int[] piles, int h) {
    int lo = 1, hi = 0;
    for (int p : piles) hi = Math.max(hi, p);
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        long hours = 0;
        for (int p : piles) hours += (p + mid - 1) / mid;   // ceil
        if (hours <= h) hi = mid;      // works -> try slower
        else            lo = mid + 1;
    }
    return lo;        // piles {3,6,7,11}, h = 8 -> 4
}

Interview traps to remember

  • The overflow: with lo = 2_000_000_000 and hi = 2_100_000_000, (lo + hi) / 2 gives -97483648. Always write lo + (hi - lo) / 2.
  • The infinite loop: if a branch sets lo = mid instead of mid + 1, lo stops moving once hi == lo + 1. Every branch must move past mid.
  • Unsorted input: Arrays.binarySearch doesn't fail on an unsorted array — it lies. On {9, 7, 5, 3, 1} searching for 9 returns -6, even though 9 sits at index 0.
  • The return value: not found gives −(insertion point) − 1, not -1. Searching 4 in {1, 3, 5, 7} returns -3. Convert back with r >= 0 ? r : -r - 1.
  • Two shapes: lo <= hi with hi = mid - 1 finds an exact value; lo < hi with hi = mid finds the smallest index that works.
  • Duplicates: plain binary search finds an occurrence. Save the index and keep shrinking to get the first or the last.

Spot it when

  • The input is sorted, or can be sorted cheaply.
  • The answer is a number in a range and you can test 'does x work?' quickly.
  • The words 'minimum', 'maximum', 'smallest x such that' or 'at most'.
  • A rotated or shifted sorted array, or a sorted matrix.

Interview tip

★ When the brute force is a loop over a sorted range, ask whether the check is monotonic. If it is, binary search it and you drop from O(n) to O(log n). And never call Arrays.binarySearch on an unsorted array — it doesn't fail, it just returns a wrong answer. On {9, 7, 5, 3, 1} searching for 9 returns -6, even though 9 is at index 0.
