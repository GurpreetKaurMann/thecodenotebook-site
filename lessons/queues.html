In simple words

A queue is First In, First Out: offer adds at the back, poll removes from the front, peek looks at the front. All O(1).

A deque is a queue you can push and pop at both ends — so one class gives you a queue, a stack and a sliding window. Use ArrayDeque by default; LinkedList is the only one that accepts null.

Think of it like…
A line at a counter. The first person to arrive is the first one served. A deque is a line people can join or leave from either end.

Key ideas

  • BFS level by level: record q.size() before the loop — that size is exactly one level. On an unweighted graph BFS also gives the shortest path for free.
  • Monotonic deque: for the maximum of every window, keep indexes with the biggest at the front and pop every smaller one from the back. A smaller number that arrived earlier can never be the maximum again. O(n) total.
  • PriorityQueue is a heap, not a queue. poll always returns the smallest; for a max-heap pass Collections.reverseOrder().
  • Kth largest: keep a min heap of size k. If it grows past k, poll. The top is your answer — O(n log k) instead of O(n log n).
  • Queue from two stacks: push onto the 'in' stack; to pop, move everything into the 'out' stack once, which flips the order. Each element moves at most twice, so pop is O(1) amortised.

Java code

// BFS level by level — LeetCode 102
List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> out = new ArrayList<>();
    if (root == null) return out;
    Queue<TreeNode> q = new ArrayDeque<>();
    q.offer(root);
    while (!q.isEmpty()) {
        int sz = q.size();                 // one whole level
        List<Integer> level = new ArrayList<>();
        for (int i = 0; i < sz; i++) {
            TreeNode cur = q.poll();
            level.add(cur.val);
            if (cur.left  != null) q.offer(cur.left);
            if (cur.right != null) q.offer(cur.right);
        }
        out.add(level);
    }
    return out;
}

// Kth largest — LeetCode 215 (min heap of size k)
int findKthLargest(int[] nums, int k) {
    PriorityQueue<Integer> pq = new PriorityQueue<>();
    for (int x : nums) {
        pq.offer(x);
        if (pq.size() > k) pq.poll();      // drop the smallest
    }
    return pq.peek();                      // [3,2,1,5,6,4], k=3 -> 4
}

Interview traps to remember

  • Printing a PriorityQueue is not sorted. Offer 5, 1, 3 and it prints [1, 5, 3] — that's the internal heap array. Only poll order is sorted.
  • Two flavours of every method: offer, poll and peek return a value; add, remove and element throw NoSuchElementException on an empty queue.
  • ArrayDeque refuses null, so poll() == null always means empty. LinkedList is the only implementation that accepts null — usually the only reason to pick it.
  • BFS levels: record int sz = q.size() before the inner loop. Reading q.size() inside the loop gives you the wrong level.
  • Kth largest: use a min heap of size k, not a max heap. The top of that heap is the answer, and it costs O(n log k).
  • Max-heap: new PriorityQueue<>(Collections.reverseOrder()).

Spot it when

  • 'Level by level', 'shortest path' on an unweighted graph, or 'nearest exit'.
  • 'Top K', 'kth largest' or 'k closest' — that's a heap of size k.
  • 'Maximum of every window of size k' — that's a monotonic deque.
  • Scheduling, merging k sorted things, or anything processed in arrival order.
