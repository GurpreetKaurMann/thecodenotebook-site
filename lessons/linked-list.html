In simple words

A linked list is a chain of nodes. Each node holds a value and a pointer to the next node. There is no index: to reach the k-th node you walk from the head.

That makes reading slow (O(n)) but inserting or removing at the head fast (O(1)) — the opposite trade-off to an array.

Think of it like…
A treasure hunt. Each clue holds one item and tells you where the next clue is. You can't jump to clue 5 — you have to follow the trail.

Key ideas

  • The dummy node trick: start with ListNode dummy = new ListNode(0) and return dummy.next. It removes a whole class of null-pointer edge cases.
  • Reverse with three pointers: prev, cur, next. Save next, flip the arrow, move both forward.
  • Slow & fast pointers: slow moves 1 step, fast moves 2. When fast hits the end, slow is at the middle.
  • Floyd's cycle detection: if there is a cycle, slow and fast always meet, because fast gains one step on slow each round. O(1) extra space — no HashSet needed.
  • Where the cycle starts: after they meet, move one pointer back to the head and move both one step at a time. They meet at the cycle's entrance.
  • Merge two sorted lists with a dummy and a tail; at the end attach whatever is left. No new nodes are created.
  • Nth from the end in one pass: move one pointer n steps ahead, then move both until it reaches the end.

Java code

// Reverse a linked list — LeetCode 206
ListNode reverse(ListNode head) {
    ListNode prev = null, cur = head;
    while (cur != null) {
        ListNode next = cur.next;   // save
        cur.next = prev;            // flip
        prev = cur;                 // move
        cur = next;
    }
    return prev;                    // new head
}

// Detect a cycle — LeetCode 141 (O(1) space)
boolean hasCycle(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) return true;
    }
    return false;
}

// Merge two sorted lists — LeetCode 21
ListNode merge(ListNode a, ListNode b) {
    ListNode dummy = new ListNode(0), tail = dummy;
    while (a != null && b != null) {
        if (a.val <= b.val) { tail.next = a; a = a.next; }
        else                { tail.next = b; b = b.next; }
        tail = tail.next;
    }
    tail.next = (a != null) ? a : b;   // the rest
    return dummy.next;
}

Interview traps to remember

  • Never index a LinkedList: list.get(i) is O(n), so a loop over it is O(n²). In interviews an ArrayList is almost always the better choice.
  • Null checks: node.next.next throws a NullPointerException the moment node.next is null. Write node.next != null && node.next.next != null.
  • Order matters: in reverse, save cur.next before you overwrite it, or you lose the rest of the list.
  • Which middle? With an even length, while (fast != null && fast.next != null) lands on the second middle. For 1→2→3→4 you get 3, not 2. Interviewers ask which one you return.
  • Cycle start (LeetCode 142): after slow and fast meet, move one pointer back to the head and move both one step at a time. They meet where the cycle begins.
  • Dummy node: use one whenever the head itself might be removed or replaced — it kills the special case.

Spot it when

  • 'Reverse', 'reorder' or 'rearrange' a list without extra memory.
  • 'Find the middle', 'detect a loop' or 'is it a palindrome'.
  • Anything that says O(1) extra space on a list — think two pointers.
  • Merging or sorting lists where you may not create new nodes.

Interview tip

★ Draw the arrows on paper before you write a line. Almost every linked-list bug is a pointer assigned in the wrong order, or a missing null check. And never call get(i) on a LinkedList in a loop — each call is O(n), so the loop becomes O(n²).
